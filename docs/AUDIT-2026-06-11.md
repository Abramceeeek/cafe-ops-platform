# Deep Audit — cafe-ops-platform — 2026-06-11

Multi-agent audit across 10 dimensions (secrets, SQL/RLS, Next.js auth, edge functions, Flutter,
ops-scripts, CI/CD, order-lifecycle correctness, quality/deps, architecture/drift). Each HIGH/CRITICAL
finding was adversarially verified by an independent skeptic agent; 11 findings were **refuted** as false

**Risk posture: HIGH — pre-launch. At least one real privilege-escalation path, one broken critical

## CRITICAL (confirmed)

### C1 — Profile UPDATE RLS allows privilege escalation
`supabase/migrations/0016_rls_hardening.sql:159-162` — **hand-verified ✅**
Policy `users_update_own_profile` is `FOR UPDATE … WITH CHECK (id = auth.uid())` with no column
restriction. Comment says "for fcm_token" but a user can run `UPDATE profiles SET role='admin' WHERE
id=auth.uid()`. Escalates immediately (if `current_role_name()` reads the table) or at next token mint
(via `custom_access_token_hook`).
**Fix:** restrict the UPDATE to the `fcm_token` column only; route fcm updates through a
`SECURITY DEFINER` RPC (see `0039_set_fcm_token_rpc.sql` — verify it's actually used and drop the broad policy). Add a WITH CHECK that role/shop_id/is_active are unchanged.

### C2 — Order can be approved with zero line items
`supabase/migrations/0037_specialist_review_rpc.sql:49-75`
Specialist can delete all items and still transition to `specialist_approved`; receipts/fulfillment
then break on an empty order.
**Fix:** after edits, `SELECT count(*) … RAISE EXCEPTION 'cannot_approve_empty_order'` before the status update.

### C3 — Missing `shop_confirmed` (Final Confirm) state — handshake incomplete
`supabase/migrations/0038_change_order_status_rpc.sql:40-47` + PROJECT_SPEC §7.2
The two-way-handshake step (specialist_approved → shop_confirmed) has no RPC/UI. Orders can't progress
to courier assignment. *(Spec gap / missing feature rather than a security bug — verify against current
product intent before building.)*
**Fix:** add `confirm_order_final` RPC + web action + Flutter flow (draft in the workflow output).

### C4 — Undefined `profile` reference crashes generate-receipt
`supabase/functions/generate-receipt/index.ts:53,83` — **hand-verified ✅**
`const profile` is block-scoped inside the `if (authHeader !== service-role)` branch but read at line 83
outside it. Service-role (internal) callers skip the branch → ReferenceError; external callers hit it out
of scope too. Receipt generation is broken on this path.
**Fix:** declare `let profile` before the branch; for internal callers fetch the order's shop and skip the
role check; guard the line-83 check with `if (profile && …)`.

### C5 — Hardcoded demo passwords in tracked scripts
`scripts/seed-roles.mjs:11`, `seed-demo.mjs:13`, `seed-specialist.mjs:13`, `seed-courier.mjs:11`,
`auth-diagnose.mjs:13`, `e2e-order-lifecycle.mjs:20` (`DemoPass123!`)
If demo accounts are seeded on the live project, anyone with the repo can authenticate.
**Fix:** read from `process.env.DEMO_PASSWORD` (no fallback, exit if unset); rotate live demo passwords now.

### C6 — Destructive ops-scripts have no production guard *(ops-scripts dimension)*
`scripts/db-wipe-orders.mjs`, `wipe-history.mjs`, `purge-users.mjs`, `delete-test-users.mjs`
`--confirm` only guards invocation typos, not which DB is targeted; a swapped `keys.txt` → irreversible
live deletion.
**Fix (≈30 min, single highest-value change):** project-ref guard in every destructive script —
```js
const ref = kv.SUPABASE_URL.match(/\/\/([a-z0-9-]+)\.supabase/)?.[1]
if (ref !== process.env.ALLOWED_DB_REF) { console.error(`ABORT: wrong DB ${ref}`); process.exit(1) }
```
